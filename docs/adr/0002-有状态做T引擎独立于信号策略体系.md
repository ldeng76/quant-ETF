# 0002 - 有状态做T引擎独立于现有无状态信号策略体系

现有盘中策略体系（`strategies/` 包 → `StrategySelector` → `monitor_alerts`）的契约是无状态的 `analyze(code, df) → StrategySignal`（纯方向信号）。做T决策天然有状态：必须知道"当前有无未平T单、机动仓剩几份、当日已T几笔、底仓可卖量"，塞进无状态接口需要把状态外置到表里每轮恢复，污染现有信号语义且容易出错。决定新建独立的 `t_trade/engine.py`（TtEngine 状态机），回测与实时共用同一决策核心；实时期复用 monitor 的数据循环时机与 `monitor_alerts` 的存储格式（signal_type 扩展 T_OPEN/T_CLOSE），但不经过 `StrategySelector`，也不注册为 `TaskRegistry` 选股任务。

## Considered Options

- 适配现有 `strategies/` 接口，状态外置表恢复：表面复用大，实际每轮状态恢复引入一致性风险，且告警语义（"两腿之一"）无法用单条方向信号表达。
- 独立状态机模块（选定）。

## Consequences

- 做T信号与现有策略信号在告警页可区分（strategy_name 不同、signal_type 扩展），但需要 Dashboard 告警页对 `T_OPEN/T_CLOSE` 的展示做少量适配（第二期）。
- `TtEngine` 必须保持"纯决策、不碰钱、不直接读写存储"，才能回测/实时双用——这是代码评审的硬约束。
