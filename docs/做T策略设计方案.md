# 做T策略实现方案（T+0 底仓回转交易）

> 依据 `docs/做T狂人_做T策略总结.html` 拆解设计；领域术语见根目录 `CONTEXT.md`。
> 状态：设计已与用户逐轮确认（Q1–Q13），待批准后实施。

## 0. 背景与目标

「做T狂人」体系一句话：96均线定方向、RSI(6)定买卖点、共振定时机、底仓5成+机动5成的仓位纪律兜底；正T/反T双向赚差价，目标摊薄底仓成本。

本项目分两期落地：

- **第一期（本方案主体）**：回测引擎 + 做T引擎 + KPI 报告（CLI + CSV/HTML），验证该策略在 ETF 池上是否有正期望的增量收益。
- **第二期（概要见 §7）**：同一套信号逻辑接实时增量数据，盘中提醒。

## 2. 策略规则规格（文章 → 可执行规则）

> 标注 ⚙ 的为参数（默认值见 §2.8）；标注【增强】的为可独立开关（默认开）；文章未量化处按"工程化解释"给出定义并在报告 params.json 中留痕。

### 2.1 指标（主级别 bar 序列上计算）

- **MA(96)** 主趋势线；MA(24)/MA(6) 仅实时期1分钟确认用，回测不用。
- **RSI(6)**：≤ ⚙`rsi_buy_th`(20) 超卖；≥ ⚙`rsi_sell_th`(80) 超买。
- **分型**（缠论标准）：底分型=连续三根 bar 中间那根低点最低、高点也最低；顶分型镜像。
- **下影线/上影线确认**：下影线长度 ≥ 2×实体 且收盘位于 bar 上半部（上影线镜像）。
- **平均振幅**：6/24/96 日窗口的日振幅均值（日线口径，来自 `market_daily`）。

### 2.2 三完全分类（方向许可）

对 MA96 计算斜率：`slope = (MA96_t − MA96_{t−n}) / MA96_{t−n}`，⚙`n=8` 根主级别 bar，⚙`slope_th=0.1%`：
slope > +th → **上行**（只许正T）；< −th → **下行**（只许反T）；其间 → **横盘**（双向）。
逆势T（上行中的反T/下行中的正T，文章"物极必反"场景）由 ⚙`allow_offside_t`（默认关）控制。

### 2.3 正T入场（开仓腿=用机动资金买入）

同时满足：

1. 方向许可（上行或横盘）；
2. RSI(6) ≤ 20（核心条件，文章核心买点）；
3. 【增强⚙`confirm_fractal`】最近已完成 bar 构成底分型，或出现下影线企稳（两者其一）；
4. 【增强⚙`confirm_volume`】底分型处成交量收缩（第三根 < 第一根）；
5. 【增强⚙`resonance`】纵向共振：高级别（主5m→15m；主15m→60m）MA96 同向（上行）；
6. 【增强⚙`index_filter`】大盘过滤：沪深300 主级别 MA96 非下行；
7. 【增强⚙`amp_filter`】⚙`amp_min`=近96日平均振幅下限，低于则当日停手（文章个股标准 3%，ETF 默认校准为 1.5%，并用池内分位数复评）；当日已实现振幅 < ⚙`amp_dead`(1.5%) 停手；
8. 【增强⚙`time_window`】买入腿仅在 09:35–11:00 窗口（文章"上午10–11点常为全天低点"；避开 9:30–9:35 开盘噪声为工程化解释）。

### 2.4 正T对冲腿（卖出等量底仓）

满足其一即触发：RSI(6) ≥ 80；或【增强】顶分型/上影线承压；或【增强⚙`dev_th`】价格高于 MA96 超过偏离阈值（"远离均线"）。偏好时段 13:30–14:30（⚙`time_window`）。
**14:55 强制对冲**（⚙`eod_force_time`）——严格当日闭环（Q5）。

### 2.5 反T（镜像）

入场=卖出底仓：方向许可（下行/横盘）∧ RSI ≥ 80 ∧【增强】顶分型或上影线 ∧ 缩量（"无量反弹"）∧ 共振下行 ∧ 大盘非上行 ∧ 振幅/时段过滤。
对冲腿=买回等量：RSI ≤ 20、底分型、偏离均线下方、14:55 强制。

### 2.6 当日闭环与 T+1 合规

- 默认严格闭环：当日未平T单一律 14:55 后按下一根 bar 开盘价强制对冲，无论盈亏（⚙`strict_eod=True`；False=允许隔夜，作为对照实验开关）。
- T+1 约束显式建模：**可卖量 = 昨日底仓余量 − 当日已卖**。正T买入的机动份额当日不可卖（本策略本来就卖底仓昨仓，规则自动满足）；账户层仍强制校验，防止参数组合出 bug。
- 等量铁律：对冲腿数量 == 开仓腿数量（账户层断言）。

### 2.7 仓位纪律

- 每标的子账户：初始资金 = 总资金/N（等权）；期初首根 bar 开盘价建满底仓（占50%），机动资金均分 10 份。
- 每 T 单默认投 ⚙`units_per_trade=1` 份；**共振窗口**（主级别+高级别+大盘三者同向）可投 ⚙`resonance_units=2` 份（"重拳出击"）。
- 同时在场 T 单 ⚙`max_concurrent=1`（"1份1份做"，做完再开）；每日上限 ⚙`max_trades_per_day=3`。

### 2.8 参数默认表（全部进 `params.json` 快照）

| 参数 | 默认 | 说明 |
|---|---|---|
| `primary_level` | `5m` | 文章对 ETF 建议 15m，作为回测矩阵对比组 |
| `resonance_level` | `15m`（主15m时为`60m`） | 纵向共振高级别 |
| `ma_len` / `rsi_len` | 96 / 6 | 文章统一参数 |
| `rsi_buy_th` / `rsi_sell_th` | 20 / 80 | 回测矩阵扫 30/70（ETF 低波动校准） |
| `slope_n` / `slope_th` | 8 / 0.1% | 三分类工程化定义 |
| `confirm_fractal` / `confirm_volume` / `resonance` / `index_filter` / `amp_filter` / `time_window` / `dev_th` | 全开 / 1.5% | 增强开关，消融实验用 |
| `amp_dead` | 1.5% | 当日振幅下限，低于停手 |
| `units_per_trade` / `resonance_units` / `max_concurrent` / `max_trades_per_day` | 1 / 2 / 1 / 3 | 仓位纪律 |
| `strict_eod` / `eod_force_time` | True / 14:55 | 当日闭环 |
| `commission_rate` / `min_commission` | 万1 / 0元 | ETF 免印花税；敏感性扫 {万0.5,万1,万2}×{0,5元} |
| `slippage` | 单边 0.05% | 敏感性扫 {0, 0.05%, 0.1%} |
| `allow_offside_t` | False | 逆势T |

## 3. 系统设计

### 3.1 模块结构

```
src/quant_etf/t_trade/
  __init__.py
  params.py      # TTradeParams dataclass：§2.8 全部参数 + to_json()
  indicators.py  # MA/RSI/分型/影线/振幅（纯函数，pandas 进出）
  classifier.py  # 三完全分类、纵向共振、大盘过滤判定（纯函数）
  engine.py      # TtEngine 状态机（见 3.2）
  account.py     # SubAccount：底仓/机动份/T+1校验/费用/摊薄成本
  backtest.py    # Backtester：数据加载→重采样→逐bar主循环
  metrics.py     # KPI：增量收益/摊薄曲线/T单统计/敏感性网格/消融
  report.py      # 输出 trades.csv / equity.csv / summary.md+html / params.json
```

CLI：`quant-etf t-backtest --codes 510300,... --start 2025-09-01 --end 2026-09-01 [--params params.json] [--matrix]`（`--matrix` 跑 §4 M4 的回测矩阵）。不注册进 `TaskRegistry`——做T是持仓驱动闭环，不是选股任务（ADR-0002）。

### 3.2 TtEngine 状态机（每标的一个实例）

状态：`IDLE → LEG1_OPEN(方向,数量,份数) → LEG2_PENDING → IDLE`；输入=当前bar+指标快照+账户状态；输出= `OPEN_T(direction, units)` / `CLOSE_T()` / `NOOP` / `FORCE_CLOSE(reason)`。
纯决策、不碰钱：所有成交经 `SubAccount` 执行并校验（T+1、等量、份余量、日上限）。状态机无时间序列回看以外的隐藏状态，回测与实时共用同一 `engine.py`（第二期只换数据驱动方式）。

### 3.3 成交模型（Q12）

信号在 bar t 收盘确认 → 以 bar t+1 开盘价成交：买入 `open*(1+slippage)`，卖出 `open*(1−slippage)`；费用=佣金（万1，min 0）。回测循环按"先全部产生信号、后统一按下一bar开盘成交"编排，结构性排除未来函数。

### 3.4 回测主循环（Backtester）

1. 加载：每标的 5m bars（PG `minute_bars`，回补见 §3.6）→ `resample_bars` 出 15m/60m；指数（沪深300）5m 同窗口。
2. 期初建仓（Q10）：首日首根 bar 开盘价建满底仓。
3. 逐日逐 5m bar：bar 收盘 → 增量更新指标 → classifier → engine 决策 → 挂"次bar开盘"委托 → 次bar开盘执行 → 14:55 触发强制闭环评估。
4. 每日收盘：核对底仓股数==期初（等量铁律断言）、记T单、结算摊薄成本。
5. 基准：同总资金等权买入并持有至期末（纯持有）。

### 3.5 KPI 与报告（Q4）

- **主口径**：组合净值曲线（做T）− 纯持有净值曲线；终值差与年化差。
- **过程指标**：每标的摊薄成本曲线；T单明细（两腿价、差价bp、方向、持仓bar数、触发标签）；统计=笔数/胜率/平均差价/正反T分解。
- **敏感性网格**：佣金×滑点×最低佣金，输出主口径差矩阵。
- **消融**：每个增强开关单独关闭重跑，输出边际贡献表（Q3 承诺）。
- 报告落 `data/results/{date}/t_trade/`，首行标注**样本区间与数据深度**（Q6）。

### 3.6 数据依赖与 M0 回补

- 审计 `minute_bars` 每标的历史深度（复用/扩展 `minute-audit`）；不足则用 `minute-fill`/`backfill` 从 pytdx 翻页回补（单次800根，目标≥1年）。
- 沪深300 5m：`tdx.py::get_index_bars` 回补入 `minute_bars`（指数代码入同表）。
- **前置阻塞**：PG（10.12.115.3）对开发机 pg_hba 拒绝直连，`.env` 仍写 localhost——M0 前需用户提供可用连接方式。

## 4. 里程碑

| # | 内容 | 验收 |
|---|---|---|
| M0 | 数据审计+回补（含指数5m） | 每标 ≥1 年 5m 或明确记录实际深度 |
| M1 | `indicators.py`+`classifier.py` | 单测：RSI对照已知序列；分型/影线构造样例；三分类三情形 |
| M2 | `engine.py`+`account.py` | 单测：正/反T两腿、14:55强平、等量断言、T+1拒绝、份耗尽、日上限 |
| M3 | `backtest.py` 合成数据 smoke | 箱体→双向T单>0；单边涨→仅正T；振幅<1.5%→零交易 |
| M4 | 真实数据+`metrics.py`+`report.py`+回测矩阵 | 报告含主口径/敏感性/消融/样本区间标注 |
| M5 | 决策点：是否二期 | 看增量收益是否在成本敏感性下仍为正 |

回测矩阵（M4）：主级别 {5m, 15m} × RSI阈值 {20/80, 30/70} × 增强消融 × 成本网格。

## 5. 风险与校准点（诚实清单）

1. **RSI(6)≤20 在 ETF 5m 上可能很稀疏**（ETF低波动）→ 信号太少。应对：阈值扫描；若仍稀疏，"该策略不适合低波 ETF 池"本身即有效结论。
2. **振幅 3% 是个股标准**，ETF 池普遍达不到 → `amp_min` 用池内分位数复评，报告中给出池内振幅分布。
3. **pytdx 5m 历史深度未知**（DB 暂不可达）→ 样本可能 <1 年，如实标注、不外推。
4. **斜率/偏离度/时段窗口为工程化解释**，博主原文无量化定义 → 全参数化，params.json 留痕，结论措辞注意"本文实现版本"。
5. 滑点 0.05%≈5bp：ETF tick 0.001 元（约1–3bp）略保守，可接受。

## 6. 第二期概要（实时提醒）

- `TtEngine` 挂进现有分钟采集回调链（`MinuteCollectorService.on_collection_complete` 同款时机），输入=最新已完成 5m bar；指标增量计算。
- 状态持久化：新表 `t_engine_state`（引擎快照）+ 信号写 `monitor_alerts`（复用其存储与告警页，`signal_type` 扩展 `T_OPEN/T_CLOSE`，reason 带T单语义）。
- 可选增强：1分钟 6/24均线交叉确认（Q7）。
- 底仓来源切换为 Dashboard `holdings` 表（真实记录持仓）而非虚拟账户。
