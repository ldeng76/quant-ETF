## 1. 核心功能缺失

### 问题描述

**回测功能缺失**

设计文档([design.md](file://E:\mw3\wspy\2025\quant-ETF\docs\design.md#L115))中明确提到需要回测验证策略,但当前项目缺少:
- 历史回测引擎
- 策略表现评估指标(夏普比率、最大回撤、年化收益等)
- 与基准指数(如沪深300)的对比分析
- 资金曲线可视化

### 用户影响

- 无法验证策略的历史表现和有效性
- 缺乏信心采用实盘交易
- 无法量化风险收益特征

### 改进建议

1. 实现回测引擎模块
   - 支持多周期回测(日线/分钟线)
   - 考虑交易成本、滑点
   - 支持仓位重平衡频率配置

2. 添加关键绩效指标(KPI)计算
   - 夏普比率、Sortino比率
   - 最大回撤及恢复时间
   - 年化收益率、月度收益表
   - 胜率、盈亏比

3. 生成回测报告
   - HTML格式详细报告
   - 资金曲线图、回撤图
   - 持仓变化时间线

## 2. 数据处理能力有限

### 问题描述

**分钟级数据未充分利用**

项目现状:
- 有monitor.py支持15分钟级别监控
- 有1分钟数据采集(minute_collector.py)
- 但日常选股任务(tasks.py)只用到日线数据
- 分钟级数据与选股流程未集成

**数据质量检查缺失**

- 没有自动的数据完整性校验
- 脏数据可能导致选股结果错误
- 停牌、除权除息处理不完善

### 用户影响

- 无法利用高频信号捕捉短期机会
- 数据质量问题可能导致错误的交易信号
- 无法进行多时间框架综合分析

### 改进建议

1. 多时间框架融合
   - 日线确定趋势方向
   - 小时线确认入场时机
   - 分钟线精准择时

2. 数据质量监控
   - 每日运行前自动校验数据完整性
   - 异常数据检测和处理
   - 数据缺失时的降级策略

3. 增强数据处理管道
   - 自动处理停牌股票(使用替代数据或跳过)
   - 正确的复权价格计算
   - 分红调整的历史数据

## 3. 输出和可视化不足

### 问题描述

**结果展示不够直观**

当前输出方式:
- 仅生成TDX导入文本文件
- 用户必须在TDX软件中才能查看结果
- 缺少本地可查看的分析报告
- 无历史结果对比追踪

### 用户影响

- 快速分析效率低,每次都要打开TDX
- 不方便向团队分享结果
- 难以直观观察策略演变趋势

### 改进建议

1. 生成HTML分析报告
   ```
   data/results/2026-03-13/
   ├── etf_report.html          # ETF选股报告
   ├── short_report.html         # 短线股票报告
   ├── mid_report.html           # 中期反弹报告
   └── comparison.html           # 三者对比
   ```

2. 报告内容包含
   - 排名前15标的详情表格
   - 动量得分构成饼图
   - 与上月持仓变化对比
   - 历史推荐表现追踪
   - 市场状态判断依据

3. 交互式仪表盘(可选高级功能)
   - Plotly/Dash或Streamlit构建
   - 支持筛选不同策略
   - 点击查看个股详情
   - 历史信号回查

## 4. 配置灵活性差

### 问题描述

**硬编码参数过多**

主要问题在[conf.py](file://E:\mw3\wspy\2025\quant-ETF\src\quant_etf\conf.py):
- ETF池写死在代码中(L32-L48)
- 权重调整需要修改源码或设环境变量
- 不同策略共用同一配置
- 无法按日期/场景切换配置

### 用户影响

- 调整策略需要改代码,风险高
- 无法快速A/B测试不同参数组合
- 团队协作时配置容易冲突

### 改进建议

1. 外部配置文件(YAML/JSON)
   ```yaml
   # config/strategies/etf_momentum.yaml
   etf_pool:
     aggressive: ["510050", "510310", ...]  # 激进型
     conservative: ["510880", "511160", ...]  # 保守型
   
   weights:
     bull_market: { r60: 0.2, r20: 0.3, r10: 0.3, r5: 0.2 }
     bear_market: { r60: 0.5, r20: 0.3, r10: 0.1, r5: 0.1 }
   
   top_n: 15
   ```

2. 命令行参数覆盖
   ```bash
   uv run python src/main.py etf \
     --top-n 20 \
     --weights r5=0.5,r10=0.3,r20=0.15,r60=0.05 \
     --pool aggressive
   ```

3. 支持配置模板
   - `config/templates/` 预置多种策略配置
   - 用户可自定义模板
   - 支持按月份自动切换(如年初重长期,年末追短期)

## 5. 调度自动化程度低

### 问题描述

**手动运行为主**

当前执行方式:
- [run_daily.py](file://E:\mw3\wspy\2025\quant-ETF\run_daily.py)需手动触发
- [monitor.py](file://E:\mw3\wspy\2025\quant-ETF\src\quant_etf\monitor.py)需长时间前台运行
- 无内置定时任务调度
- 无开机自启/服务化部署方案

### 用户影响

- 非技术人员使用门槛高
- 休假时容易漏跑任务
- 生产环境稳定性差

### 改进建议

1. 集成APScheduler
   ```python
   # 盘中定时任务
   - 9:00  预热数据,获取昨日选股结果
   - 9:25  集合竞价数据分析
   - 11:30 午间盘点
   - 15:00 收盘后运行选股任务
   - 22:00 更新次日数据
   ```

2. 系统服务部署
   - 提供systemd service文件(Windows/Linux)
   - Docker容器化部署方案
   - 进程守护和健康检查

3. 任务队列支持
   - Celery/RQ异步任务队列
   - 支持并发执行多个策略
   - 任务失败自动重试

## 6. 错误处理和容错

### 问题描述

**异常情况处理不够细致**

现有问题:
- 单个ETF数据获取失败可能导致整体任务中断
- 网络超时时无重试机制
- 数据不全时程序直接报错退出
- 缺少局部失败的优雅降级

### 用户影响

- 一次网络抖动导致全天任务失败
- 个别标的数据异常影响整个选股结果
- 排查错误信息不清晰

### 改进建议

1. 隔离式错误处理
   ```python
   for code in ETF_POOL:
       try:
           data = fetch_data(code)
       except Exception as e:
           logger.warning(f"{code} 数据获取失败: {e}, 跳过")
           failed_codes.append(code)
           continue
   ```

2. 智能降级策略
   - 60日数据缺失 → 使用40日替代
   - 20日数据缺失 → 使用30日替代
   - 至少要有5日数据才参与计算
   - 标注数据质量等级(A/B/C/D)

3. 详细错误日志
   - 记录每次失败的详细信息
   - 汇总报告中的失败统计
   - 提供一键导出失败清单

4. 重试机制
   - 网络请求指数退避重试
   - 最多重试3次
   - 备用服务器自动切换

## 7. 性能优化

### 问题描述

**大规模数据效率问题**

性能瓶颈:
- 同时处理70+标的,每次全量重新计算
- 无缓存机制,重复计算相同指标
- 串行处理,未利用多核CPU
- 历史数据回溯速度慢

### 用户影响

- 运行时间随标的数量线性增长
- 盘中实时响应慢
- 开发迭代时需反复等待

### 改进建议

1. 缓存中间结果
   ```python
   # 使用DuckDB或SQLite缓存
   - 原始K线数据缓存(压缩存储)
   - 日频指标缓存(动量得分、均线等)
   - 只增量更新当日新数据
   ```

2. 并行计算
   - asyncio异步数据获取(并发请求)
   - multiprocessing并行计算各标的指标
   - joblib分布式计算(可选)

3. 数据库索引优化
   - 对交易日、股票代码建立复合索引
   - 分区表按年份/品种
   - 物化视图预聚合常用查询

4. 内存优化
   - 大数据块使用PyArrow提升性能
   - 按需加载历史数据(windowed read)
   - 及时释放不再使用的资源

## 8. 监控和告警

### 问题描述

**监控功能单一**

现状:
- monitor.py仅支持盘中15分钟级盯盘
- 无选股任务执行状态监控
- 无结果质量检查
- 无通知推送机制

### 用户影响

- 任务失败不知道,可能连续多天未执行
- 无法远程掌握系统运行状态
- 错过重要交易信号

### 改进建议

1. 任务执行监控
   ```yaml
   监控指标:
     - 任务开始/结束时间
     - 成功/失败状态
     - 选出品数量
     - 最高得分变化
     - 数据完整性百分比
   ```

2. 多渠道通知
   - 企业微信机器人(Webhook)
   - 钉钉机器人
   - 邮件通知(yagmail)
   - 飞书机器人

3. 告警规则
   - 任务连续失败2次 → 紧急告警
   - 数据缺失超过10% → 警告
   - 选股结果突变(超3个新品) → 提示
   - 市场极端行情 → 风控提醒

4. 历史仪表盘(可选)
   - Grafana + InfluxDB
   - 显示历史执行趋势
   - 策略表现统计

## 9. 策略管理

### 问题描述

**策略扩展困难**

架构问题:
- 新策略需要修改源代码(main.py/taks.py)
- 策略参数分散在各文件中
- 无法动态加载外部策略
- 策略版本管理混乱

### 用户影响

- 每次加策略都要发版
- 无法实验性测试新策略
- 团队协作时代码冲突频繁

### 改进建议

1. 策略插件化架构
   ```python
   # 策略注册机制
   @register_strategy(name="custom_momentum", version="1.0")
   class CustomMomentumTask(BaseStrategy):
       def analyze(self):
           # 自定义逻辑
           pass
       
       def score(self, data):
           return custom_score
   ```

2. 配置文件定义策略
   ```yaml
   # config/strategies/custom.yaml
   name: mean_reversion
   type: pullback  # 回调买入
   execution: daily
   
   parameters:
     lookback: 60
     entry_rsi_below: 30
     exit_rsi_above: 70
   
   pool_filter:
     min_volume: 10000000
     exclude_st: true
   ```

3. 策略版本管理
   - Git submodule或独立仓库
   - 策略兼容性检查
   - A/B测试框架

4. 策略库共享
   - 社区贡献策略市场
   - 策略评分和排行
   - 回测对比工具
